Overview

A self-contained demo that streams live pixels from a real macOS window (Safari) into a plain HTML <canvas> and routes all user input — clicks, keyboard, scroll, drag, resize — back to that native window. The canvas is served to both an Electron shell and a browser, with the capture pipeline running as a local server. Verification is done end-to-end through MCP CDP + CUA tooling.

This is a developer proof-of-concept, not a product. The bar is: open Safari, stream it into the canvas, click a link on the canvas, and Safari navigates.

Capture pipe

  • SCContentFilter(desktopIndependentWindow:) — window stays live if occluded
  • IOSurface frames → encode H.264 in-process
  • Crop to contentRect from SCStreamFrameInfo
  • Push encoded chunks over WebSocket to local server

Input pipe

  • Canvas pointer events → map to window screen coords
  • CGEventCreateMouseEvent for click/drag/scroll
  • CGEventCreateKeyboardEvent for key input
  • AX API for window move/resize

Requirements

F1
Live pixel stream

Canvas renders ≥24fps live frames from the target macOS window. Frame drop causes no crash; stream recovers automatically.

core
F2
Click passthrough

Pointer down/up on canvas translates to a CGEvent mouse click at the correct screen position in the native window. Link navigation in Safari is the acceptance test.

core
F3
Keyboard passthrough

Keydown/keyup on the canvas sends CGEventCreateKeyboardEvent to the target window. Text entry in a text field works.

core
F4
Scroll passthrough

Wheel events on the canvas produce kCGScrollWheelEvent in the native window. Page scrolls in Safari.

core
F5
Window drag / resize from canvas

Dragging the window chrome in the canvas moves the native window (AX setPosition). Corner drag resizes it.

v1

Dual consumer

Same WebSocket stream is consumed by both Electron and a plain browser tab. Both render the same frame at the same time.

core
F7
MCP + CUA test coverage

The demo is driven and verified by MCP CDP (browser automation) and CUA (computer-use agent). A test script opens Safari, streams it, clicks a link via the canvas, and asserts navigation succeeded.

core

Coordinate Mapping

The canvas shape and the native window live in two different coordinate spaces. Every input event requires this transform: 

// canvas event → native screen point
const scaleX = windowContentWidth / canvas.width;
const scaleY = windowContentHeight / canvas.height;

const screenX = windowOriginX + (canvasX * scaleX);
const screenY = windowOriginY + (canvasY * scaleY);

// send to input-bridge over WebSocket
ws.send(JSON.stringify({
  type: 'click',
  x: screenX, y: screenY,
  button: 'left',
  clickCount: 1
}));

Window origin and content size are tracked via Accessibility API and updated whenever the native window moves or resizes. The canvas client receives these as a side-channel message from the local server.

Constraints & Known Limits

⚠
Screen Recording permission required. The capture helper needs TCC Screen Recording grant. First launch will prompt.
⚠
Accessibility permission required. The input bridge needs TCC Accessibility grant for CGEvent posting and AX window control.
⚠
Minimized windows stop streaming. SCContentFilter(desktopIndependentWindow:) pauses on minimize. Keep the target window on an active Space (or a virtual display).
⚠
DRM / protected content will not capture. Netflix and similar apps set sharingType = .none. Safari general browsing is fine.
⚠
Retina scaling. IOSurface is at backing scale (2×). Divide by contentScale from SCStreamFrameInfo to get logical point sizes before coordinate mapping.

Milestones

1

Capture helper skeleton

Swift CLI that streams a given CGWindowID over WebSocket as raw H.264 NAL units. Crops to contentRect. Logs fps and frame size.

2

Canvas client decodes + renders

Browser page uses VideoDecoder (WebCodecs) to decode the H.264 stream and paint frames to <canvas> at ≥24fps.

3

Input bridge live

Canvas pointer/keyboard/scroll events round-trip through local server → Swift input bridge → CGEvent → native window. Click test passes.

4

Electron shell

Electron window hosts the canvas client. Both Electron and browser tab consume the same stream simultaneously.

5

MCP CDP + CUA test pass

All 8 test steps in the test plan pass. Safari click-through on canvas is the headline result.

Out of Scope (this demo)

  • Multi-window tiling or infinite canvas layout
  • Remote streaming (everything is local)
  • Audio capture
  • Cursor synchronization (real macOS cursor is not synced to canvas pointer)
  • App injection or SIP workarounds
  • Windows other than Safari for initial testing
